# 03 评测方案

## 目标指标

- 偏好提取准确率 >= 85%
- 知识检索召回率 >= 85%
- 知识检索响应延迟 P95 <= 500ms
- 知识冲突处理正确率 >= 88%
- 敏感信息识别 F1 >= 90%

每项至少50次独立请求，银河麒麟V11强制部署，SDK为推荐项。当前内部证据及分母见 `docs/32_第五轮验收报告.md`；行动评测见 `docs/26_官方行动评测协议.md`。重复同一道题不能补足独立样本。

## 当前逐请求验收

`request_regression_v1.json`冻结数据摘要及初始失败见 `docs/30_逐请求评测与冻结基线.md`。偏好68请求按完整键值集合匹配，知识60正例按Recall@3，冲突60组按检测和最终状态联合评分，敏感50请求按实体类型/精确值微平均F1。性能为80个不同查询、10,000条记录上的实际MemoryService.search，nearest-rank P95，不预热、不含HTTP或Agent推理。

```powershell
python -S scripts/evaluate_requests.py --size 10000 --require-targets --output artifacts/runtime/requests.json
```

除五项数值与分母外，持久化授权、知识入库、12个无答案、8个跨域及脱敏泄漏分别为硬门槛。提取准确不等于允许长期持久化；开发者持有公开标签，不称为第三方盲测。

除原有准确率外，评测器同时报告下列可复核指标：

- 偏好、冲突、遗忘：微平均 Precision、Recall、F1。
- 知识检索：Precision@K、Recall@K、MRR、nDCG@K；无答案查询仅在系统正确返回空集合时计 1 分。
- 遗忘误删率：`未授权删除数 / 实际删除总数`，无删除时记为 0。

偏好预测中多报的键值按假阳性计入 Precision；遗忘评测只统计本次操作实际影响的 ID，并将标注目标以外的任何删除视为误删。

## 数据集设计

评测数据集建议分为四类：

1. 偏好抽取集：输入多源事件，标注应抽取的偏好键值。
2. 知识检索集：输入知识库和查询，标注应召回的知识 ID。
3. 冲突处理集：输入新旧知识对，标注是否冲突以及正确处理方式。
4. 遗忘指令集：输入自然语言遗忘请求，标注应删除或保留的记忆。

## 实验设计

需要至少做三组对比：

1. 规则基线：当前原型，低依赖、可解释。
2. embedding 检索：接入银河麒麟 embedding SDK 后的检索版本。
3. 混合策略：规则、embedding、置信度融合和冲突检测联合使用。

## 报告内容

测试报告需要包含：

- 数据集来源、规模、字段说明和标注规则。
- 运行环境，尤其是银河麒麟桌面系统版本、CPU、内存。
- 指标定义和计算方式。
- 对比实验表格。
- 未达标指标的原因和优化方向。

## 当前可运行评测

当前 `src/os_agent_memory/evaluation.py` 已提供：

- 偏好准确率计算函数。
- 检索召回率计算函数。
- 平均检索延迟统计函数。
- 冲突处理准确率评测函数，支持校验冲突识别和可选解决策略结果。
- 自然语言遗忘准确率评测函数。
- smoke evaluation，用于确认原型链路可运行。
- 标注评测 suite runner，用于从 JSON 标注集直接输出核心指标和逐用例明细。

v1 小型兼容回归集位于 `data/eval/office_memory_eval.json`，覆盖办公报销和会议纪要场景：

- 11 条多源事件。
- 9 条偏好标注。
- 6 条知识检索查询。
- 4 条冲突处理用例。
- 3 条自然语言遗忘用例。

运行命令：

```powershell
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli evaluate --suite ".\data\eval\office_memory_eval.json" --top-k 3 --summary-only --output ".\artifacts\runtime\v1_report.json"
```

v1仅为历史兼容诊断。旧标签含单条低证据事件，在当前生命周期和授权门槛下有未达项，不沿用2026-09-05的旧满分。

`evaluate` 输出中的 `details` 字段用于研发定位和答辩说明：

- `details.preferences`：记录每个偏好标注的期望值、预测值、置信度、版本、场景和证据 ID。
- `details.retrieval`：记录每个查询的期望标题、实际返回标题、命中标题、单条召回率和是否通过。
- `details.conflicts`：记录每个冲突用例的期望冲突、实际冲突、冲突对象数量、解决策略、新旧知识最终状态和合并内容。
- `details.forget`：记录每条遗忘指令的关键词解析结果、期望遗忘/保留标题、实际遗忘标题、漏删和误删列表。

注意：v1/v2保留为历史诊断，v3作为隔离检索回归；当前五项以冻结逐请求数据为准。独立盲测需由未参与开发的评测者另行保管标签执行。

## 扩展分区评测集

`data/eval/office_memory_eval_v2.json` 由 `scripts/generate_eval_v2.py` 确定性生成，共 120 条事件，按 train/dev/test 各 40 条隔离。数据覆盖报销、会议、公文、文件归档、终端安全、客户邮件 6 类核心场景，以及通用系统噪声；同时包含同义查询、失败工具、提示注入、无答案、知识冲突和跨用户私有记忆。

```powershell
python .\scripts\generate_eval_v2.py
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli evaluate --suite ".\data\eval\office_memory_eval_v2.json" --split test --top-k 3 --summary-only
```

本数据集全部为合成数据，生成器、来源类型和分区用途记录在 JSON 的 `provenance` 与 `split_policy` 字段。仓库中的 test 标签对开发者可见，因此只能作为“冻结测试分区”，不能表述成第三方独立盲测；正式盲测需要由未参与开发的评测者另行保管标签。

## 规模性能基准

以下命令使用同一检索实现依次构建 100、1000、5000、10000 条知识，报告首次冷查询、后续热查询 p50/p95/p99、吞吐、Python 峰值内存和 SQLite 文件体积：

```powershell
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli benchmark --sizes 100,1000,5000,10000 --rounds 30 --top-k 5 --output-json ".\artifacts\runtime\performance.json" --output-md ".\artifacts\runtime\performance.md"
```

规模报告只证明当前provider与测量范围的趋势；HashEmbedding不等于原生SDK，热p99不等于逐请求P95。V11已有HashEmbedding实测，原生模型性能需独立复测。
