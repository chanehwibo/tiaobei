# 正式评测资源与外部交接

2026-09-09。主办方认可虚拟机、运行资源和评分口径已按参赛者确认推进，
不重复申请。以下是现有实现的接入与真实证据要求，不是再次征求认可。

## 只读运行前核验

已有`check_action_runtime.py`只盘点PATH和选定环境变量是否存在。
新增`check_action_readiness.py`进一步核对冻结清单、控制器源码、V11身份、
容器服务端资源及本地固定镜像。仅执行有界的`info`和`image inspect`，
不拉取、不安装、不启动容器、不联系模型。输出不含命令原文、隐藏标签或凭据。

未获得私有清单时可以先运行环境检查，缺项退出2：

```powershell
python -X utf8 -S scripts/check_action_readiness.py --output artifacts/runtime/readiness-new.json
```

在隔离V11内，先按照第26号文档冻结真实样例及身份，再执行：

```bash
python3 -X utf8 -S scripts/check_action_readiness.py \
  --sample /home/tiaobei/controller/private-sample.json \
  --manifest /home/tiaobei/controller/run-manifest.json \
  --engine docker --output /home/tiaobei/controller/readiness-new.json
```

全部静态项通过仍退出3，表示需实际运行。源码变化、未来冻结时间、镜像ID或
架构不符均不能通过。引擎总内存至少2 GiB只是最低容量检查，不是可用内存、
模型峰值或部署成功证明。镜像`size_bytes`为磁盘体积，不与RSS等同。

## 资源交接清单

| 内容 | 接收及核对要求 | 当前边界 |
| --- | --- | --- |
| Agent程序与适配器 | 来源、许可、版本；固定镜像ID；镜像内绝对入口；输入输出协议 | 尚未收到可运行的获准Agent镜像 |
| 独立Judge | 不同于Agent的固定模型、完整模型manifest/blob及摘要、模型许可 | 尚未收到实际模型和可用镜像 |
| 容器引擎 | 隔离V11内Docker或Podman服务端版本，Linux和匹配CPU架构 | 宿主客户端存在不等于客户机引擎可达 |
| 运行资源 | 每容器2 CPU、2 GiB、128进程、64 MiB临时目录；记录真实峰值、OOM、耗时 | 不根据镜像大小推定能运行 |
| Judge上下文 | 32768 token上下文，最多12288 token输出，单次调用总上限600秒 | 字节上限不保证token适配；必须完整评分 |
| 隐藏样例 | 第三方持有、逐项语义审核、冻结及交接时间、五项各至少50个独立请求 | 公开替身及合成回归不能变成盲测 |
| 认可原件 | 原始文件、来源、时间、适用V11/VM/资源和评分版本 | 已收到参赛者确认，原件仍需真实归档 |

接收后先核对来源、许可及摘要，不在宿主启动模型。按第26号文档执行单样本单容器、
会话重置、结束后冻结文件、独立Judge、全部0分项及至少10%人工抽检。
若资源不够，保留失败、OOM和超时原件；不得降低分母、忽略截断或把资源盘点改为成功。
变更获准资源配置后须重新冻结和实测，不能沿用旧延迟。

## 外部证据归档

实际文件放私有实验目录，公开仓库只放脱敏索引和核验结论；不在Git存放密钥、
隐藏标签、用户原始记录、签字盖章件或联系方式。

| 项目 | 完成所需原件 | 可以自动做的部分 | 不能自动代替的部分 |
| --- | --- | --- | --- |
| X01 | 原始Agent轨迹、文件、模型响应、标签交接及人工复核记录 | 格式、摘要、覆盖率、指标重算和失败留证 | 独立方身份、未泄漏标签的事实、人的实际复核 |
| X02 | 已获认可的原始凭证及配置对应表 | 对照版本、摘要及配置差异 | 认可方身份和凭证真实性 |
| X03 | 真实参与者授权、匿名化案例、撤回渠道及核验记录 | 脱敏扫描、材料完整性检查 | 本人同意与真实应用经历 |
| X04 | 最终不超过7分钟视频、实际画面复核、平台审核、盖章报名表 | 时长/编码检查、文件摘要、Office内容比对 | 画面隐私确认、平台批准、签章真实性 |
| X05 | 最终确认的提交包、实际提交时间和回执 | 新草案封存、解包复算、文件清单 | 正式发送授权、平台提交或邮件送达事实 |

仓库的`incomplete_draft`可以用于交接技术材料，不能仅因文件存在改为正式就绪。
现有公开50轮行动样例的76个检查共享一个样本，不能计成76个独立请求。
五项指标保持85%/85%/88%/500ms/90%，每项至少50个独立请求；人工分歧必须保留并裁决。

## 复测顺序

1. 冻结源码和配置，完成Windows与磁盘安装V11的同源复验。
2. 获取并核验上述实际资源，运行只读预检；静态通过后再按协议执行真实Agent/Judge。
3. 由独立方完成隐藏数据测试和人工复核，使用实际逐请求分母重新验收。
4. 将真实外部材料和最新技术证据组包、复核视频和文档，再确认正式发送及回执。

当前公开预检报告只能证明它实际检查过的范围，不证明全盘没有模型或主办方未认可。
