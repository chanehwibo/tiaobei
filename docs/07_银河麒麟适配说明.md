官方资料明确要求银河麒麟V11，SDK为推荐项。已完成V11磁盘安装、客户机测试及五项逐请求回归，详见 [V11实测](31_麒麟V11客户机实测.md)；虚拟机部署形式仍待赛事认可。真实C ABI使用 `provider=kylin-native`，详见 [真实SDK接入](27_真实SDK接入与证据边界.md)。以下Python模块配置保留为通用支架，不代表官方存在这样的Python包。

## 已取得的实测证据

- Windows和V11客户机使用同一冻结逐请求数据、HashEmbedding256维、10,000条记录，五项内部门槛通过。
- 安装的Embedding旧ABI在有界启动AI Runtime后成功返回768维有限非零向量；单探针13390.615ms，不是P95。
- 新ABI缺少所需符号；默认模型身份/版本未确认。旧ABI仅显式诊断，不作为业务provider的静默回退。
- 向量服务active，但数据库往返和开发依赖未就绪；真实Agent/容器/独立Judge尚未执行。

## SDK 适配配置

适配器不假设发榜单位 SDK 的固定 Python 接口，可配置：

- `module_name`：可导入的模块名；
- `factory_name`：可选客户端工厂或类；
- `factory_kwargs`：传给工厂的参数；
- `method_name`：接收文本的向量方法；
- `response_path`：返回对象内向量的点分路径，例如 `data.embedding` 或 `data.0.vector`。

自检示例：

```powershell
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli kylin-sdk-check --module "实际模块名" --factory "实际客户端工厂" --method "实际方法" --response-path "data.embedding" --factory-kwargs '{"model":"实际模型名"}' --output ".\artifacts\verification\kylin_sdk_check.json"
```

通过条件为：模块可导入、工厂可调用、方法存在、返回路径有效、向量非空且全部为有限数。报告只记录工厂参数名称，不回显参数值，避免访问令牌进入交付材料。

## 当前边界

仓库内HashEmbedding是显式选择的离线基线，不是发榜单位SDK。单探针成功不足以称为完成适配；需确认模型身份、参数、真实业务provider、数据库往返，并在认可的V11部署中完成相同功能与性能复测。

## 环境一键自检

```powershell
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli compat-check --workspace . --output-json ".\artifacts\verification\compatibility_windows_dev.json" --output-md ".\artifacts\verification\compatibility_windows_dev.md"
```

如已取得 SDK，可追加 `--sdk-module`、`--sdk-factory`、`--sdk-method` 和 `--sdk-response-path`。报告会分别判断本地运行条件、真实银河麒麟识别和真实 SDK 自检，不会因为普通开发机测试通过就标记赛题指定环境就绪。
