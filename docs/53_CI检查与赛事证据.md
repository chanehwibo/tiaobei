# CI检查与赛事证据

默认 push、pull request 和手动运行执行 Windows/Linux × Python 3.10/3.14 工程矩阵：
完整测试、源码检查、安装、冻结指标、历史材料结构检查、消融、服务压测和行动框架自检。
每个环境的 `ci-*.json` 报告在失败后也上传为 GitHub Actions 工件，保存14天。
Action版本固定到已核验的官方v7提交；同分支同事件的新任务取消旧任务。

当前源码的严格双环境材料验收独立为 `competition_readiness` 作业。
手动运行工作流时勾选 `verify_competition` 才执行；原生成器的证据、源码摘要和V11要求均未放宽。
当前仍缺最新V11和真实SDK等证据，严格作业应失败，不能用普通工程矩阵的绿灯宣称赛事验收完成。

本地复现严格检查：

```powershell
python -X utf8 -S scripts/generate_takeover_materials.py --check-only --report artifacts/runtime/current-materials.json
```

未提交的本地Office删除或正文修订不会出现在GitHub的检出目录里。应分别检查：

- Git提交快照：用于代码回归及源码包复现。
- 工作文件夹：用于正在编辑的答辩材料、视频和真实案例验收。

已发布的历史材料只证明其原版本；更改算法后须重新绑定证据，不能给旧Office自动换成新测试数字。
