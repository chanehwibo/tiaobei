# 原创性、数据来源与隐私发布边界

更新时间：2026-09-05

## 1. 适用范围

本说明约束源代码仓库、答辩 PPT、技术报告、测试报告、演示视频、报名材料和现场演示。它用于回答“哪些内容是团队实现的、哪些来自第三方、哪些可以公开、哪些只能私下提交”。

## 2. 项目原创范围

当前仓库由项目团队编写和维护的主要成果包括：

- 多源事件模型、校验、去重、递归脱敏和记忆污染检测；
- 偏好记忆的维度化、作用域、版本、置信度、权威度和生命周期处理；
- 知识记忆的混合检索、冲突隔离、自动/人工消歧和无答案拒答；
- 两阶段自然语言遗忘、软删除/硬删除、索引同步和隐私安全回执；
- SQLite 持久化、服务层、本地 Web 演示、诊断、评测和性能基准；
- 合成样例、确定性评测集生成脚本、测试用例和比赛交付文档。

Git 提交历史是研发过程的主要可追溯证据。若团队成员、指导教师或外部贡献者新增实质内容，应在提交记录和最终报名材料中如实列明。

## 3. 非原创或外部范围

- Python、`python-pptx`、`python-docx` 及其依赖属于第三方软件，详见根目录 `THIRD_PARTY_NOTICES.md`。
- 银河麒麟操作系统、embedding SDK、系统 API、商标和文档属于相应权利人，本仓库只提供可配置适配接口，不分发这些资源。
- 真实用户案例、授权书、报名表、获奖证明、学校盖章文件和平台回执属于外部材料，不能用仓库中的模板替代。
- 由生成式工具辅助形成的文字、图示或代码应由团队复核其正确性、原创性、许可和可披露范围；团队仍对最终提交负责。

## 4. 合成数据声明

仓库内公开数据仅用于测试和演示，是人工编写或由 `scripts/generate_eval_v2.py` 确定性生成的虚构记录。它不能证明真实用户效果，也不能代替独立盲测或真实办公场景验收。

若收集真实案例，必须先取得可证明的知情同意，限定目的、字段、保存周期、访问人员和撤回方式；采集后立即去标识化，并将原始授权和映射表放在仓库之外的受控位置。

## 5. 发布分级

| 级别 | 内容 | 处理规则 |
| --- | --- | --- |
| 可公开 | 源代码、合成数据、脱敏报告、通用架构图 | 完成许可证和敏感信息扫描后可进入公开仓库 |
| 仅评审 | 已授权且脱敏的真实案例、必要的证明扫描件 | 只通过赛事指定私密渠道提交，不进入 Git |
| 严格保密 | 身份证件、手机号、住址、签字原件、账号密码、SDK 密钥、数据映射表 | 不进入公开提交物；按最小权限单独保存 |
| 禁止收集 | 与比赛目标无关的敏感个人信息 | 不采集、不处理、不保留 |

## 6. 提交前强制检查

1. 检查 Git 暂存区、历史、压缩包和演示数据库，不只检查工作区可见文件。
2. 确认 `.env`、密钥、Token、Cookie、真实联系方式、报名表和授权原件未进入公开包。
3. 对截图、终端标题栏、浏览器书签、文件路径、通知弹窗和视频音轨进行人工复核。
4. 引用论文、图片、图标或数据集时补齐来源与许可证；没有明确授权就不使用。
5. “麒麟已验证”“真实用户已验证”“已提交成功”等结论必须附对应原始证据，否则只能写为待完成或计划项。

## 7. 事故处理

一旦发现误提交的个人信息或凭据，应立即停止分发、吊销凭据、限制仓库访问并联系材料接收方。仅删除最新文件不足以清除 Git 历史，应由仓库负责人评估历史重写和强制推送；执行前必须另行确认影响范围并通知协作者。
