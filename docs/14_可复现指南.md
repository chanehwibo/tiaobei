# 从干净克隆复现实验

## 1. 固定源码

```powershell
git clone https://github.com/chanehwibo/tiaobei.git
cd tiaobei
git rev-parse HEAD
git status --short
```

记录 HEAD；`git status --short` 应为空。最终归档还应对照 SHA-256 清单。

## 2. 准备隔离环境

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -e .
python --version
```

核心功能无第三方运行依赖。重新生成 PPT 或 Word 技术报告才需要项目的 `deliverables` 可选依赖。

## 3. 重建合成评测集

```powershell
python .\scripts\generate_eval_v2.py
git diff --exit-code -- ".\data\eval\office_memory_eval_v2.json"
python .\scripts\generate_eval_v3.py
git diff --exit-code -- ".\data\eval\office_memory_eval_v3.json"
```

无差异证明生成器具有确定性。该数据是合成数据，不是实际用户案例。

## 4. 全量测试

```powershell
$env:PYTHONPATH="$PWD\src"
python -m unittest discover -s tests -v
python -m compileall -q src tests
```

结果必须为 `OK`。测试数以当前 HEAD 为准，不依赖文档中的历史数字。

## 5. v3 质量门槛与 v1/v2 历史诊断

```powershell
python -m os_agent_memory.cli evaluate --suite ".\data\eval\office_memory_eval.json" --top-k 3 --summary-only --output ".\artifacts\runtime\evaluation_v1.json"
python -m os_agent_memory.cli evaluate --suite ".\data\eval\office_memory_eval_v2.json" --split test --top-k 3 --summary-only --output ".\artifacts\runtime\evaluation_v2_test.json"
python scripts/evaluate_v3.py --require-quality --output artifacts/runtime/evaluation_v3.json
```

v3 两项 quality_targets 必须同时为 true，--require-quality 未达到时返回非零；固定 test 分母为 12 正例、6 无答案，统一阈值仅来自 dev。当前 11/12 与 6/6，不是独立盲测。v1/v2 旧标签含单条低证据输入，生命周期门控后有目标未满足，作为诊断保留，禁止降低门槛或改标签把它们标绿。延迟随机器负载变化，不要只复制历史值。

## 6. 四档性能基准

```powershell
python -m os_agent_memory.cli benchmark --sizes 100,1000,5000,10000 --rounds 30 --top-k 5 --output-json ".\artifacts\runtime\performance.json" --output-md ".\artifacts\runtime\performance.md"
```

记录 environment、每档冷查询、热 p50/p95/p99、QPS、内存和 SQLite 体积。真实 SDK 与真实银河麒麟必须分别重跑，不沿用 Windows/HashEmbedding 数字。

## 7. 环境与 SDK

```powershell
python -m os_agent_memory.cli compat-check --workspace . --output-json ".\artifacts\runtime\compatibility.json" --output-md ".\artifacts\runtime\compatibility.md"
python -m os_agent_memory.cli kylin-sdk-check --module "实际SDK模块" --output ".\artifacts\runtime\sdk.json"
```

没有真实 SDK 时第二条应如实失败或 unavailable；不得构造 ready 报告。

## 8. 一键演示

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_demo.ps1" -NoServer
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_demo.ps1" -SkipTests
```

第一条验收命令链；第二条启动本地 Web。浏览器访问终端显示的 localhost 地址。

## 9. 结果核对

- 生成器重建无 Git 差异。
- 全部测试通过。
- v3 两项各 ≥85% 且分母不变；v1/v2 未达项如实保留。
- 四档性能报告字段完整，环境与 embedding 身份准确。
- 兼容性报告没有把 Windows 标为银河麒麟。
- SDK 缺失时没有标记 ready。
- 运行时文件只在 `artifacts/runtime/`，不污染固定证据。

如果任一项失败，应保存失败输出、修复后重新执行完整链路；不得只重跑或截取单个成功步骤。
