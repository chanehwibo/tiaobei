# OS Agent 多源融合记忆优化系统技术方案

版本：已完成初版，待赛事验收
更新时间：2026-09-11
对应赛题：XA-202612 OS Agent 记忆优化及高效应用研究

## 摘要

本项目面向桌面操作系统智能体在长期使用中出现的偏好漂移、知识冲突、检索延迟、敏感信息残留和跨用户串读等问题，设计一套端侧优先的多源记忆优化系统。系统将手动配置、用户行为、会话上下文、系统事件、工具结果和导入文档统一为带租户、用户、会话、有效时间、来源权威度和隐私级别的事件；经过校验、去重、递归脱敏和记忆污染检测后，分别形成偏好记忆与知识记忆，并通过短期—中期—长期生命周期控制降低一次性噪声进入长期记忆的风险。

检索采用“轻量词法候选召回 + embedding 语义重排 + 权威度融合”，查询向量只计算一次，文档向量在入库时缓存。知识冲突默认进入隔离状态，普通回答不可见，再按照来源权威度、有效时间和版本决策。自然语言遗忘采用预览计划、确认令牌、软/硬删除、索引同步和隐私安全审计回执，所有操作均绑定租户与用户作用域。

当前仓库已形成标准库原型、增量 SQLite 持久化、统一生命周期服务、本地场景演示、分区评测和规模基准，并支持Markdown/YAML授权记忆、按需召回、逐项确认遗忘、50轮行动评测框架与真实Embedding C ABI诊断。历史版本在Windows和已安装的V11虚拟机上执行冻结逐请求评测；原始证据见 artifacts/verification/round5/，各阶段数据保留为历史内部回归。本次反馈落实和新源码结果以第37号文档为准，不沿用旧源码的部署通过结论。

官方强制部署为银河麒麟V11；目标为偏好准确率≥85%、知识召回率≥85%、冲突正确率≥88%、检索P95≤500ms、敏感识别F1≥90%，每项至少50独立请求。SDK属于推荐项。五项内部回归已满足数值和请求数要求；标签由开发者持有，行动替身自检不能替代真实Agent或独立Judge成绩。

## 1. 问题定义与目标

### 1.1 核心问题

传统“把历史对话全部拼接进提示词”的记忆方式存在五类缺陷：

1. 多源信息缺少统一语义，失败工具、偶发点击和显式配置可能被等权处理。
2. 复合偏好被压缩成单一标签，无法同时表达语言、详略、格式、安全和工具选择。
3. 新旧知识并存时可能把相互矛盾内容同时返回，造成操作建议不一致。
4. 全量向量计算随数据增长退化，端侧资源占用和响应时延不可控。
5. 遗忘范围模糊，容易漏删、误删或跨用户删除，审计又可能二次泄露原文。

### 1.2 设计目标

- 支持六类事件来源的统一接入、校验、脱敏、错误隔离和证据追踪。
- 同时维护多维偏好与结构化知识，支持版本、有效时间、场景和访问作用域。
- 建立短期、聚合中期、受控长期的可解释流转。
- 默认隔离未决冲突，低相关查询允许明确返回无答案。
- 在端侧完成遗忘预览、确认、删除、索引同步和审计。
- 提供评测、性能报告、SQLite、服务接口和本地可视化。
- 对真实银河麒麟、真实 SDK、独立盲测和真实案例保持证据诚实。

### 1.3 非目标与边界

当前版本不替代企业权限系统、数据防泄漏系统或数据库备份治理；不对未获得的 SDK 接口作虚构实现；不把合成数据测试表述为真实业务收益；不把 Windows 开发机性能表述为银河麒麟实测性能。

## 3. 总体架构

```text
工具结果 / 用户行为 / 手动配置 / 会话 / 系统事件 / 导入文档
                         │
                         ▼
          校验 → 时间归一 → 去重 → 递归脱敏 → 风险标记
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
      多维偏好抽取               知识结构化抽取
             │                       │
             └───────────┬───────────┘
                         ▼
         短期 TTL → 中期聚合/评分 → 长期记忆
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
  SQLite v2       冲突隔离与决策      混合检索索引
        │                │                │
        └────────────────┼────────────────┘
                         ▼
     MemoryService → JSON API → 本地 Web 仪表盘 / OS Agent
                         │
                         ▼
        遗忘预览 → 用户确认 → 删除/索引同步 → 审计回执
```

系统默认单进程端侧运行，Web 服务仅监听 `127.0.0.1`。核心层不依赖 Web，可作为 Python 包嵌入 OS Agent；embedding 通过统一协议注入，开发期使用 HashEmbedding，取得真实 SDK 后切换 KylinEmbeddingProvider。

## 4. 统一数据模型

### 4.1 事件记录

`DataRecord` 包含事件 ID、租户、用户、会话、来源、场景、正文、UTC 时间、工具状态、来源权威度、隐私级别、TTL、质量分和风险标记。主作用域为 `(tenant_id, user_id)`；会话级数据额外受 `session_id` 限定。

### 4.2 偏好记忆

偏好以 `(tenant_id, user_id, key)` 为当前版本键，保存 value、confidence、version、scenes、evidence_ids、valid_from、valid_to、tier 和 score_components。当前覆盖语言、详略、格式、结构、本地处理、脱敏、执行确认和场景工具偏好。同值证据合并，不同值生成新版本并闭合旧版本有效期。

### 4.3 知识记忆

知识保存标题、正文、标签、来源 ID、类型、场景、权威度、隐私级别、有效期、生命周期、状态、冲突对象和缓存向量。状态包括 active、conflict_pending、forgotten、expired、quarantined；普通检索只返回 active。

## 5. 输入治理与安全入口

1. 每条记录独立规范化，单条错误不会终止整批处理。
2. ISO 时间统一转 UTC；来源、隐私级别、TTL、元数据类型和权威度强校验。
3. 按 ID 与内容指纹去重，批次报告返回位置、原因和重复数。
4. 对正文及任意深度元数据递归脱敏，覆盖电话、邮箱、身份证、银行卡、IPv4、常见密钥、Bearer token 和私钥标记。
5. 对“忽略先前指令”“泄露系统提示”“永久记住”“绕过限制”等模式标记风险并降权；带风险事件不得自动形成长期知识。
6. 失败和取消的工具结果权威度下降，且不得成为工具偏好证据。

## 6. 偏好决策算法

单条证据评分为：

```text
base_score = 0.30 × quality + 0.35 × authority + 0.20 + 0.15 × explicitness
evidence_score = min(base_score, 0.99) × recency
```

隐式证据整体按30天半衰期衰减：`recency = 0.5^(age_days/30)`，参考时间按租户和用户分别确定。
显式手动设置的recency保持1，直到显式修改；风险事件不推进偏好参考时间。
显式配置的显式性权重最高，行为和会话依次降低。工具偏好另乘执行结果和用户选择反馈权重；
同工具成功证据累加，再用胜出占比校准置信度。该机制处理“晚输入的旧事件覆盖新偏好”和“失败工具误学为首选”，定向诊断不等于长期真实用户收益。

## 7. 短期—中期—长期流转

- 短期：会话缓冲区，默认 TTL 30 分钟，按租户、用户、会话检索。
- 中期：按租户、用户、场景、主题聚合，统计次数、来源多样性、质量、权威和风险。
- 长期：通过可解释门控晋升；默认至少两条证据，或显式权威度达到 0.9。

```text
promotion = 0.30 × average_quality
          + 0.30 × average_authority
          + 0.25 × repetition
          + 0.15 × source_diversity
```

存在风险时评分乘 0.35 并拒绝晋升。长期记忆支持过期和降级，每次决策保留分数与原因。

## 8. 知识冲突治理

冲突检测限定同租户、同用户、相近标签/标题范围，识别允许/禁止、可以/不可以、必须/无需、保留/删除、本地/云端等对立。候选冲突先进入 `conflict_pending`，不参与普通回答。

自动策略按照 `(authority, effective_time, version)` 比较；差异不足进入人工复核。支持接受新版本、保留现有、保留双方、证据合并和人工队列。“合并”只合并来源、标签和证据，不把矛盾句子拼接成一个答案。

## 9. 混合检索与无答案

入库缓存文档向量并建立词法、汉字及有符号向量维度倒排。查询先按作用域、状态、有效期和场景过滤，合并词法、汉字、近似语义三路候选，查询向量只编码一次后重排；近似语义召回可能引入干扰，需要对照实验。中文融合分数：

```text
score = 0.25 × semantic + 0.25 × lexical + 0.45 × character + 0.05 × authority
```

无中文证据时使用原向量 0.65、词法 0.30、权威度 0.05 配方。低于 `min_score`（默认 0.265）不返回，允许明确无答案。向量随 SQLite v2 持久化，遗忘时同步清理全部索引和向量。

当前使用倒排交集计数、有界堆候选选择、明确作用域快速路径和有界时间解析缓存；
不缓存查询答案或权限。历史等输出优化中，1万条/75%相似填充的首轮P95由67.755ms
降至39.023ms，全部1,440对输出ID、顺序和分数一致；该配对不是当前源码测量。
历史默认在复杂数据上仍有近主题误返回；相似度阈值不能可靠判定事实是否有支持。
数据冻结、历史质量分层和本地消融见`docs/40_复杂场景与检索性能复测.md`，
当前优化验收见`docs/45_复杂拒答与完整召回优化验收.md`。

新增可选`required_terms`，由调用方显式给出实体/版本，要求逐项在标题或正文中匹配，
不以标签或source_id代替证据；编号/版本按边界检查，兼容全半角及大小写。
先缩小授权候选再重排，空候选不编码查询。另冻结6场景48请求，
与原120请求分开计分；实体过滤的历史收益及局限见`docs/41_复杂约束场景补测.md`。

当前默认`focused_evidence_v2`聚焦明确请求、归一中文数量，在缺显式约束时保留无歧义的
格式化设备/版本身份；多主体歧义拒答，显式非空约束优先。主种子达到0.265后，按精确
同主题章节补全互补证据，并对实际返回标题/正文执行固定0.5覆盖和属性片段检查。
补全章节的顶层分数是证据束相关度，响应另保留文档/片段/直接分数及来源；
它不是章节独立相似度或正确概率。普通关键词查找保持原排序和分数，
以`ranked_lookup`标记，不声称回答已经验证。不读取评测标签，元数据标签和来源ID不能替代
正文支持；不缓存原始问题或答案。

两套复杂集的1千/1万条、0%/75%相似填充、三轮中，新策略正例完整召回及无答案正确率
均100%；原集多文档12/12、约束集6/6找齐，约束开/关均通过。
逐请求比较保护旧默认和旧实验原本正确的请求及每题Recall，排序与干扰汇总不劣于旧默认。
1万条/75%三轮P95：原集67.605/66.067/66.724ms，约束开启16.150/15.600/15.456ms，
关闭16.447/15.452/15.696ms。全部低于500ms，原集仍有额外证据检查开销，
不声称普遍或等输出加速。该配置返回干扰仍为39/123和9/39，不等于零干扰。

旧`content_coverage_v1`仍作非默认对照，其长背景/同义反例0/6召回的失败保留于
`docs/44_正文证据检查与反例.md`。新策略在同6题已全部召回，无答案4/4正确；
初始20题亦全部通过。这是公开失败后的回归修复，不是语义蕴含、通用多跳推理或独立泛化证明。

## 10. 自然语言遗忘与审计

1. 解析主题词，生成只属于指定 tenant/user 的计划。
2. 返回关键词、偏好 ID、知识 ID、删除类型和过期时间，此时不修改数据。
3. 客户端以计划 ID、tenant_id、user_id 确认；过期或作用域不匹配拒绝，已成功确认的同作用域请求返回原回执。
4. 软删除更新状态，硬删除移除记录；两者均同步索引和向量。
5. 审计只记录计划 ID、目标 ID 和数量，不记录原指令或正文。

评测将本次操作的影响目标与完整授权集合比对，多删任何未授权目标都计入误删率；冲突处理此前淘汰的知识不会误算为本次遗忘。

## 11. 持久化、服务与界面

SQLite 保存偏好、历史、知识、向量、审计、决策以及阶段证据和去重摘要；主键差异增量提交，服务失败回滚，单进程读写串行，重启恢复阶段证据。MemoryService 提供接入、检索、冲突、遗忘、概览与专属租户演示接口。

本地 HTTP 服务限制请求体 1MB，默认不记录业务内容并设置不缓存响应；仪表盘覆盖接入、偏好、检索、冲突和遗忘。该界面用于本地演示，不等同生产服务；跨主机开放前需增加认证、TLS、CSRF 防护和速率限制。

## 12. 银河麒麟与 SDK 适配

KylinEmbeddingProvider 保留为通用Python模块适配支架；新增kylin-native依据公开C ABI调用真实共享库，使用独立子进程限制超时和崩溃，校验维度及有限非零向量，最终释放会话与结果。不会静默回退为HashEmbedding。向量数据库公开接口是C++客户端，当前真实服务桥接待验证。环境严格识别银河麒麟V11，库存在、Embedding连通、向量数据库连通及正式就绪分别报告。

V11历史磁盘安装与测试见 `docs/31_麒麟V11客户机实测.md`；历史HTTP曾受系统网络管控影响，当前源码部署需独立复验。主办方对虚拟机部署、运行资源和评分口径已按参赛者确认获认可，原件待归档。

**真实SDK时延：待复测风险项。** 旧ABI返回768维有限非零向量的单次耗时为13,390.615ms，
包含进程、会话及初始化，不是至少50请求的P95。当前provider每次调用都会建立隔离进程，
不能假定后续调用会自动省去这部分时间。新ABI缺符号、实际模型身份与版本未核验、
向量数据库建库/写/查/删往返待验证。HashEmbedding成绩不得作为原生性能证明。
解除风险条件和完整风险表见 `docs/27_真实SDK接入与证据边界.md`。

## 13. 评测设计与结果

统一评测口径见`docs/39_评测口径与可信度.md`，按反馈中的性能可信度25分组织证据。
其中明确宏/微平均、固定分母、无答案误答、越域泄漏、异常处理、冷/后续轮时延及模型边界。
复杂干扰集独立计分，不改变既有五项的冻结数据；不自行承诺评分或把内部回归写成认证。

当前验收使用 `request_regression_v1.json`，原始字节摘要冻结。偏好68请求按完整键值集合评分，多报和漏报都计错；60个知识正例以Recall@3评分，另查12个无答案及8个跨作用域请求；60组冲突联合检查检测与最终状态；敏感识别50请求使用实体类型及精确值的微平均F1。长期持久化授权、入库、无答案、跨域和脱敏泄漏分别作为安全硬门槛，不通过放松生命周期提高分数。

## 15. 方案特点

1. 从单标签画像升级为有证据、场景、时间和版本的多维偏好。
2. 将安全贯穿入口、生命周期、检索、遗忘和审计。
3. 用候选召回与向量缓存控制端侧时延，并保留可替换 SDK。
4. 冲突默认不可见、决策可追溯，不用矛盾拼接冒充融合。
5. 把误删、无答案、多报偏好纳入指标，避免小样本虚高。
6. 自动区分本地能力与外部未验收项，提高材料可信度。

### 15.1 相关工作对比与技术创新性

按反馈中的技术创新性30分组织论证，详细矩阵、一手文献及实验入口见
`docs/38_相关工作与创新边界.md`。MemGPT的分层上下文、MemoryBank的长期记忆与遗忘、
Generative Agents的观察/反思/规划、LongMem的训练式记忆读取及FAISS的向量检索，
分别提供相关研究背景。本项目没有复现这些完整系统，也不比较跨任务论文数字。

可辩护的差异是面向桌面事件的授权晋升、显式偏好与弱行为的可追溯决策、
冲突隔离和作用域一致性、两阶段遗忘，以及模型可替换的多路候选检索与逐请求证据链。
缓存、时间衰减、倒排和向量重排本身不是首创；HashEmbedding不代表预训练模型的语义能力。
现有仅词法/仅向量/混合、缓存、衰减及冲突隔离消融只能支持局部工程贡献，
真实Agent收益和独立数据泛化需要另行验证。

近期直接相关的Mem0、MemoryOS以及LongMemEval/LongMemEval-V2另见
`docs/43_近期相关工作与评测对照.md`。三层记忆与OS类比已有先例，不能作为首创；
公开基准提醒我们区分状态更新、跨会话证据、前提识别和最终阅读。
本项目未运行这些外部基准，不挪用论文成绩，也不将合成检索片段命中等同任务成功。
