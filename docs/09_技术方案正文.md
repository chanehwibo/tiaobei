# OS Agent 多源融合记忆优化系统技术方案

版本：第四轮（官方口径整改草案）
更新时间：2026-09-07
对应赛题：XA-202612 OS Agent 记忆优化及高效应用研究

## 摘要

本项目面向桌面操作系统智能体在长期使用中出现的偏好漂移、知识冲突、检索延迟、敏感信息残留和跨用户串读等问题，设计一套端侧优先的多源记忆优化系统。系统将手动配置、用户行为、会话上下文、系统事件、工具结果和导入文档统一为带租户、用户、会话、有效时间、来源权威度和隐私级别的事件；经过校验、去重、递归脱敏和记忆污染检测后，分别形成偏好记忆与知识记忆，并通过短期—中期—长期生命周期控制降低一次性噪声进入长期记忆的风险。

检索采用“轻量词法候选召回 + embedding 语义重排 + 权威度融合”，查询向量只计算一次，文档向量在入库时缓存。知识冲突默认进入隔离状态，普通回答不可见，再按照来源权威度、有效时间和版本决策。自然语言遗忘采用预览计划、确认令牌、软/硬删除、索引同步和隐私安全审计回执，所有操作均绑定租户与用户作用域。

当前仓库已形成标准库原型、增量 SQLite 持久化、统一生命周期服务、本地场景演示、分区评测和规模基准。第四轮新增Markdown/YAML授权记忆、按需召回、逐项确认遗忘、50轮行动评测框架与真实Embedding C ABI适配。当前证据见 artifacts/verification/round4/evidence_summary.json 和《第四轮验收报告》；第三轮数据保留为历史内部回归。

官方强制部署为银河麒麟V11；目标为偏好准确率≥85%、知识召回率≥85%、冲突正确率≥88%、检索P95≤500ms、敏感识别F1≥90%，每项至少50独立请求。SDK属于推荐项。当前偏好准确率及部分样本数仍不足，行动替身自检不能替代真实Agent或独立Judge成绩。

## 1. 问题定义与目标

### 1.1 核心问题

传统“把历史对话全部拼接进提示词”的记忆方式存在五类缺陷：

1. 多源信息缺少统一语义，失败工具、偶发点击和显式配置可能被等权处理。
2. 复合偏好被压缩成单一标签，无法同时表达语言、详略、格式、安全和工具选择。
3. 新旧知识并存时可能把相互矛盾内容同时返回，造成操作建议不一致。
4. 全量向量计算随数据增长退化，端侧资源占用和响应时延不可控。
5. 遗忘范围模糊，容易漏删、误删或跨用户删除，审计又可能二次泄露原文。

### 1.2 设计目标

- 支持六类事件来源的统一接入、校验、脱敏、错误隔离和证据追踪。
- 同时维护多维偏好与结构化知识，支持版本、有效时间、场景和访问作用域。
- 建立短期、聚合中期、受控长期的可解释流转。
- 默认隔离未决冲突，低相关查询允许明确返回无答案。
- 在端侧完成遗忘预览、确认、删除、索引同步和审计。
- 提供评测、性能报告、SQLite、服务接口和本地可视化。
- 对真实银河麒麟、真实 SDK、独立盲测和真实案例保持证据诚实。

### 1.3 非目标与边界

当前版本不替代企业权限系统、数据防泄漏系统或数据库备份治理；不对未获得的 SDK 接口作虚构实现；不把合成数据测试表述为真实业务收益；不把 Windows 开发机性能表述为银河麒麟实测性能。

## 3. 总体架构

```text
工具结果 / 用户行为 / 手动配置 / 会话 / 系统事件 / 导入文档
                         │
                         ▼
          校验 → 时间归一 → 去重 → 递归脱敏 → 风险标记
                         │
             ┌───────────┴───────────┐
             ▼                       ▼
      多维偏好抽取               知识结构化抽取
             │                       │
             └───────────┬───────────┘
                         ▼
         短期 TTL → 中期聚合/评分 → 长期记忆
                         │
        ┌────────────────┼────────────────┐
        ▼                ▼                ▼
  SQLite v2       冲突隔离与决策      混合检索索引
        │                │                │
        └────────────────┼────────────────┘
                         ▼
     MemoryService → JSON API → 本地 Web 仪表盘 / OS Agent
                         │
                         ▼
        遗忘预览 → 用户确认 → 删除/索引同步 → 审计回执
```

系统默认单进程端侧运行，Web 服务仅监听 `127.0.0.1`。核心层不依赖 Web，可作为 Python 包嵌入 OS Agent；embedding 通过统一协议注入，开发期使用 HashEmbedding，取得真实 SDK 后切换 KylinEmbeddingProvider。

## 4. 统一数据模型

### 4.1 事件记录

`DataRecord` 包含事件 ID、租户、用户、会话、来源、场景、正文、UTC 时间、工具状态、来源权威度、隐私级别、TTL、质量分和风险标记。主作用域为 `(tenant_id, user_id)`；会话级数据额外受 `session_id` 限定。

### 4.2 偏好记忆

偏好以 `(tenant_id, user_id, key)` 为当前版本键，保存 value、confidence、version、scenes、evidence_ids、valid_from、valid_to、tier 和 score_components。当前覆盖语言、详略、格式、结构、本地处理、脱敏、执行确认和场景工具偏好。同值证据合并，不同值生成新版本并闭合旧版本有效期。

### 4.3 知识记忆

知识保存标题、正文、标签、来源 ID、类型、场景、权威度、隐私级别、有效期、生命周期、状态、冲突对象和缓存向量。状态包括 active、conflict_pending、forgotten、expired、quarantined；普通检索只返回 active。

## 5. 输入治理与安全入口

1. 每条记录独立规范化，单条错误不会终止整批处理。
2. ISO 时间统一转 UTC；来源、隐私级别、TTL、元数据类型和权威度强校验。
3. 按 ID 与内容指纹去重，批次报告返回位置、原因和重复数。
4. 对正文及任意深度元数据递归脱敏，覆盖电话、邮箱、身份证、银行卡、IPv4、常见密钥、Bearer token 和私钥标记。
5. 对“忽略先前指令”“泄露系统提示”“永久记住”“绕过限制”等模式标记风险并降权；带风险事件不得自动形成长期知识。
6. 失败和取消的工具结果权威度下降，且不得成为工具偏好证据。

## 6. 偏好决策算法

单条证据评分为：

```text
evidence_score = 0.30 × quality
               + 0.35 × authority
               + 0.20 × recency
               + 0.15 × explicitness
```

时间权重采用 30 天半衰期：`recency = 0.5^(age_days/30)`。显式配置权重最高，行为和会话依次降低。工具偏好另乘执行结果和用户选择反馈权重；同工具成功证据累加，再用胜出占比校准置信度。该机制解决“晚输入的旧事件覆盖新偏好”和“失败工具误学为首选”。

## 7. 短期—中期—长期流转

- 短期：会话缓冲区，默认 TTL 30 分钟，按租户、用户、会话检索。
- 中期：按租户、用户、场景、主题聚合，统计次数、来源多样性、质量、权威和风险。
- 长期：通过可解释门控晋升；默认至少两条证据，或显式权威度达到 0.9。

```text
promotion = 0.30 × average_quality
          + 0.30 × average_authority
          + 0.25 × repetition
          + 0.15 × source_diversity
```

存在风险时评分乘 0.35 并拒绝晋升。长期记忆支持过期和降级，每次决策保留分数与原因。

## 8. 知识冲突治理

冲突检测限定同租户、同用户、相近标签/标题范围，识别允许/禁止、可以/不可以、必须/无需、保留/删除、本地/云端等对立。候选冲突先进入 `conflict_pending`，不参与普通回答。

自动策略按照 `(authority, effective_time, version)` 比较；差异不足进入人工复核。支持接受新版本、保留现有、保留双方、证据合并和人工队列。“合并”只合并来源、标签和证据，不把矛盾句子拼接成一个答案。

## 9. 混合检索与无答案

入库缓存文档向量并建立词法、汉字及有符号向量维度倒排。查询先按作用域、状态、有效期和场景过滤，合并词法、汉字、近似语义三路候选，查询向量只编码一次后重排；近似语义召回可能引入干扰，需要对照实验。中文融合分数：

```text
score = 0.25 × semantic + 0.25 × lexical + 0.45 × character + 0.05 × authority
```

无中文证据时使用原向量 0.65、词法 0.30、权威度 0.05 配方。低于 `min_score`（默认 0.265）不返回，允许明确无答案。向量随 SQLite v2 持久化，遗忘时同步清理全部索引和向量。

## 10. 自然语言遗忘与审计

1. 解析主题词，生成只属于指定 tenant/user 的计划。
2. 返回关键词、偏好 ID、知识 ID、删除类型和过期时间，此时不修改数据。
3. 客户端以计划 ID、tenant_id、user_id 确认；过期或作用域不匹配拒绝，已成功确认的同作用域请求返回原回执。
4. 软删除更新状态，硬删除移除记录；两者均同步索引和向量。
5. 审计只记录计划 ID、目标 ID 和数量，不记录原指令或正文。

评测将本次操作的影响目标与完整授权集合比对，多删任何未授权目标都计入误删率；冲突处理此前淘汰的知识不会误算为本次遗忘。

## 11. 持久化、服务与界面

SQLite 保存偏好、历史、知识、向量、审计、决策以及阶段证据和去重摘要；主键差异增量提交，服务失败回滚，单进程读写串行，重启恢复阶段证据。MemoryService 提供接入、检索、冲突、遗忘、概览与专属租户演示接口。

本地 HTTP 服务限制请求体 1MB，默认不记录业务内容并设置不缓存响应；仪表盘覆盖接入、偏好、检索、冲突和遗忘。该界面用于本地演示，不等同生产服务；跨主机开放前需增加认证、TLS、CSRF 防护和速率限制。

## 12. 银河麒麟与 SDK 适配

KylinEmbeddingProvider 保留为通用Python模块适配支架；新增kylin-native依据公开C ABI调用真实共享库，使用独立子进程限制超时和崩溃，校验维度及有限非零向量，最终释放会话与结果。不会静默回退为HashEmbedding。向量数据库公开接口是C++客户端，当前真实服务桥接未完成。环境严格识别银河麒麟V11，库存在、Embedding连通、向量数据库连通及正式就绪分别报告。

当前真实系统和真实 SDK 均未验证，不能在答辩中宣称完成指定环境适配。

## 13. 评测设计与结果

v1/v2 保留为历史标签诊断：这些标签含单条低证据，按当前服务晋升门槛执行后有目标未满足。v3 为正文及模板族隔离的 42 事件、18 主题、54 查询，包含正例改写、无答案及跨用户干扰。

第三轮增加正文汉字覆盖及候选路径。中文评分为向量 0.25、词法 0.25、汉字覆盖 0.45、权威度 0.05；元数据不提供汉字证据，作用域与删除状态先过滤。仅用 dev 的两項均 ≥85% 最宽连续阈值区间中心定参数，不可行时报告平衡分回退。混合阈值为 0.265，服务与 HTTP 默认一致；test 正例 11/12（91.67%）、无答案 6/6（100%），两项目标达到。首次 0.225 的未通过结果仍保留；不能沿用旧 v1/v2 的 1.0。

规模检索与实际服务负载分别报告，后者包含接入、SQLite、重启及混合读写和 HTTP。当前数据统一见 docs/22_第三轮验收报告.md 和 artifacts/verification/round3/；公开 test 被开发者多次接触，不能视为独立盲测。10k 热查询 p99 362.265ms，内存峰值 245.124MB；增加汉字索引后较第二轮延迟与内存上升，仍满足本次 500ms 门槛，不宣称性能全面提升或真实 SDK 泛化。

## 14. 威胁模型

| 威胁 | 当前措施 | 剩余风险 |
| --- | --- | --- |
| 跨租户串读 | 强制作用域、歧义拒绝、对抗测试 | 上层身份必须可信 |
| 提示注入污染 | 模式检测、降权、拒绝晋升 | 变体攻击需扩充 |
| 敏感信息持久化 | 正文/元数据递归脱敏 | 图像附件需另处理 |
| 失败工具误学习 | 状态降权、排除失败证据 | 工具可能伪报成功 |
| 未决冲突误回答 | 默认隔离 | 自动规则需专家监督 |
| 模糊指令误删 | 预览、确认、作用域、评测 | 批量操作需强审批 |
| 审计二次泄露 | 不记录原文和原始指令 | 目标 ID 仍属内部元数据 |

## 15. 方案特点

1. 从单标签画像升级为有证据、场景、时间和版本的多维偏好。
2. 将安全贯穿入口、生命周期、检索、遗忘和审计。
3. 用候选召回与向量缓存控制端侧时延，并保留可替换 SDK。
4. 冲突默认不可见、决策可追溯，不用矛盾拼接冒充融合。
5. 把误删、无答案、多报偏好纳入指标，避免小样本虚高。
6. 自动区分本地能力与外部未验收项，提高材料可信度。

## 16. 外部闭环计划

1. 从发榜单位取得真实 SDK、模型、数据和指定银河麒麟版本。
2. 在指定架构复跑自检、全部测试、v2 评测与 10,000 条基准。
3. 由未参与开发者保管独立盲测标签并出具结果。
4. 经书面同意完成真实案例，记录基线、任务级数据、负面结果和匿名化复核。
5. 核对平台审核、盖章报名表、邮件名称和回执。

## 17. 结论

本方案把 OS Agent 记忆管理从历史堆叠改造成有作用域、有证据、有生命周期、有冲突治理、有遗忘审计的端侧闭环。现有源码和开发机证据支持进入真实银河麒麟与 SDK 联调，但在外部测试完成前，项目状态应表述为“核心原型与开发机验证完成，赛题指定环境待验收”。
