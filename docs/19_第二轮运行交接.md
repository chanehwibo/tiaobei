# 第二轮运行与交付交接

## 运行

在项目根目录执行 python -m pip install -e .，再执行：

    python -m os_agent_memory.cli serve --input data/samples/events.jsonl --database artifacts/runtime/demo.sqlite

访问 http://127.0.0.1:8765 。点击“恢复演示样例”进入 local-demo/presenter 专属合成租户；
依次演示偏好变化、规则冲突、检索、预览遗忘、确认删除。再次恢复只清理合成演示空间。
真实业务接入使用独立租户；本地 API 的 tenant/user 应由可信上层绑定。

## 验收与重生成

1. python -S -m unittest discover -s tests -v
2. python scripts/check_source.py
3. node scripts/check_dashboard.cjs（可选 Node.js，仅校验前端脚本）
4. python scripts/evaluate_v3.py --embedding-config config/embedding.hash.json
5. python scripts/benchmark_service.py --sizes 100,1000 --rounds 30
6. python scripts/verify_release.py --artifact-dir artifacts/runtime/verification --sizes 100,1000,5000,10000 --rounds 30

固定第二轮证据在 artifacts/verification/round2；runtime 下的复跑不会覆盖固定证据。
如需更新正式内部证据，先保留旧报告，再用 --artifact-dir 指定固定目录重新验收，
并同步 round2_service_after.json。然后按顺序运行 generate_evidence_materials.py、
generate_ppt.py、generate_technical_doc.py（均在 scripts 下），最后重打包。
PPT/Word 依赖见 pyproject.toml 的 deliverables 选项。

## 结果解释

工程回归通过、内部质量目标满足、赛事环境通过是三种不同结论。
第二轮工程回归通过；内部 v3 混合检索目标仍未全部满足，结果与词法基线的取舍见验收报告。
数据和 test 标签均由开发者掌握，后续算法调整曾接触 test；不能宣称独立盲测或开放泛化。
语义候选增加了召回路径，也可能扩大干扰。下一步算法研究应优先在 train/dev 分析错误，
真实验证缺失时也不能把 HashEmbedding 当作麒麟 SDK。

## 当前边界

- 单进程串行写入；SQLite 增量提交仍比较状态，回滚快照有成本。
- SDK 超时隔离为单个后台线程，无法强制结束 SDK 内部调用；不得持续创建新线程补偿。
- 近似向量候选不是完整向量数据库；复杂条件冲突仍是启发式。
- 软删除保留正文用于撤回审计；硬删除清除当前记录和阶段证据，外部备份另行管理。
- CI 覆盖 Windows/Linux 和 Python 3.10/3.14；以 GitHub Actions 实际记录为准。

CI 配置依据官方 [checkout](https://github.com/actions/checkout)、
[setup-python](https://github.com/actions/setup-python) 使用说明。真实麒麟验收仍需单独执行。
