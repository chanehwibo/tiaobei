## 高频答辩问答

### 1. 你们的创新点是什么？

不是单点模型，而是端侧记忆治理闭环：多维偏好证据化、短中长期门控、冲突默认隔离、候选召回与向量缓存、两阶段安全遗忘，以及会处罚假阳性和误删的评测体系。

### 2. 是否已经接入真实银河麒麟 embedding SDK？

尚未。已完成可配置适配器和自检，当前归档报告明确为 unavailable。取得发榜单位 SDK 后，只需配置模块、工厂、方法和返回路径，但仍必须重新跑功能与性能测试。

### 3. 你们如何证明 500ms？

目前只能证明 Windows/HashEmbedding 开发机：10k 冷查询 246.796ms、热 p99 362.265ms。较第二轮增加延迟与内存，仍低于本次 500ms 门槛。不能用它证明真实 SDK 达标；最终证据必须来自指定银河麒麟版本、真实 SDK 和同一基准脚本。

### 4. 为什么很多指标是 1.0，是否过拟合？

旧 v1/v2 曾出现满分，但不能沿用。新 v3 内容隔离，dev 可用区间中心阈值 0.265 后，test 正例 11/12、无答案 6/6，两项均达到 85%。仍有 1 条漏召回；标签公开且重复接触，仅是内部回归，不证明开放域、真实 SDK 或统计泛化。

### 5. 偏好如何随时间变化？

证据按事件时间计算 30 天半衰期，不按输入顺序；同值聚合，不同值生成新版本并闭合旧版本有效期，可按版本或时间点回溯。

### 6. 为什么失败工具不会污染偏好？

输入层把失败/取消结果默认权威度降到 0.15，偏好抽取层再次明确排除 failed/cancelled 和 user_rejected 证据。

### 7. 冲突检测会误报吗？

会，因此未决冲突默认不进入回答。自动策略只有在权威或时效差异足够明确时选择胜出项，否则留在人工复核队列。

### 8. 为什么不直接使用大型向量数据库？

赛题强调端侧与资源效率。当前规模下 SQLite + 内存倒排 + 缓存向量依赖少、可审计、易部署。更大规模可将 EmbeddingProvider 和存储接口替换为专用后端。

### 9. 如何防止跨用户串读？

记忆模型以 tenant+user 为主作用域；多租户或多用户时缺少作用域参数直接拒绝。检索和遗忘都有跨租户对抗测试。

### 10. 遗忘为什么需要两阶段？

自然语言有歧义。预览让用户看到关键词和准确目标，确认令牌有过期时间；只有确认后才修改数据，可显著降低不可逆误删。

### 11. 软删除是否算真正遗忘？

软删除用于可审计的业务撤回，不再参与检索且清空向量；若法规或用户要求物理删除，应选择硬删除，并结合备份、日志和外部副本治理。

### 12. 审计日志会不会泄露被删除内容？

日志不保存原指令和正文，只保存计划 ID、目标 ID、数量和删除类型；但目标 ID 仍是内部元数据，应受访问控制。

### 13. 规则方法能应对复杂语言吗？

当前是可解释基线。架构已经把 embedding 和抽取边界独立，下一步可加入小模型或 SDK，但必须继续经过作用域、安全门控和同一评测体系。

### 14. 10k 时内存 178.782MB 是否合理？

这是 Python 对象、倒排索引和 256 维列表向量的 tracemalloc 峰值。可用紧凑 float 数组、批量映射或磁盘向量索引进一步下降；真实 SDK 向量维度必须重新测量。

### 15. 真实案例在哪里？

仓库提供了知情同意、量化记录和匿名化模板，但尚未虚构填写。需在参与者书面同意后执行，并只发布匿名聚合结果。

### 16. Web 界面可以生产部署吗？

当前只监听 localhost，用于答辩演示。当前已有跨源拒绝、确认幂等和单进程事务；生产化还需认证、TLS、限流及多进程一致性治理。

### 17. 原型怎样接入 OS Agent？

Agent 调用 MemoryService 或本地 JSON API：任务前读取场景偏好和知识，任务后写入工具结果，冲突进入治理流，遗忘走预览确认接口。

### 18. 项目失败时的降级策略是什么？

已配置 SDK 调用异常或超时会报错；开发机可显式选择 Hash 配置并标记。检索低置信返回空，冲突保持隔离，持久化失败回滚，未确认不执行高风险遗忘。

### 19. 如何保证原创性？

所有核心实现、生成器和测试均在 Git 中逐任务提交；第三方依赖与数据来源单独列明。最终材料应保留提交历史和 SHA-256 清单。

### 20. 下一步最关键的四件事？

取得真实 SDK、在指定银河麒麟实测、组织独立盲测、完成经授权真实案例。四项缺一，都不能宣称赛题环境全部达标。
