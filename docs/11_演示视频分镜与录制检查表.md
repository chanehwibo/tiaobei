建议成片时长：6 分 30 秒

目标文件名：`OS_Agent_记忆优化_演示视频.mp4`

## 1. 录制前布置

1. 将系统缩放调至 100% 或 125%，终端字号调至 20—24，浏览器缩放 110%。
2. 关闭通知、聊天软件、邮箱、网盘同步弹窗和包含姓名的浏览器标签。
3. 新建干净的本地浏览器配置，不展示账号头像、收藏夹、历史记录和密码管理器。
4. 终端执行 `[Console]::OutputEncoding = [System.Text.Encoding]::UTF8`。
5. 先运行一次 `run_demo.ps1 -NoServer`，确认预检、评测和全部测试成功。
6. 打开 PPT、技术方案、test 评测报告和性能报告，按分镜顺序排好窗口。
7. 使用 `-Port 8766` 作为备用端口；准备一份已录好的无声操作片段以防现场程序异常。

## 3. 逐段旁白与操作

### 00:00—00:15 开场

旁白：

> 本项目面向银河麒麟 OS Agent，构建一套多源融合记忆优化系统。它追求的不是记住更多，而是记得正确、找得快速、忘得安全。

操作：显示 PPT 封面，停留至少 3 秒；项目名和赛题号必须清晰。

### 00:15—00:45 问题与架构

旁白：

> 传统历史堆叠会把显式配置、偶发行为和失败工具混为一谈，也会让新旧规则同时进入回答。我们的链路先统一六类来源，经过校验、去重、脱敏和投毒检测，再分别形成偏好与知识，并由生命周期、冲突、检索和遗忘模块治理。

操作：依次圈出输入、安全入口、偏好/知识、生命周期和服务层。

### 00:45—01:15 环境预检

命令：

```powershell
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli doctor --workspace . --input ".\data\samples\events.jsonl" --suite ".\data\eval\office_memory_eval_v2.json" --host 127.0.0.1 --port 8765
```

旁白：

> 预检会检查 Python、输入文件、写权限、SQLite FTS5 和端口。当前本地阻断项全部通过；真实银河麒麟和真实 SDK 显示 warning。它们不阻断开发演示，但我们不会把 Windows 结果冒充赛题指定环境结果。

### 01:15—02:00 多源接入与脱敏

启动：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File ".\scripts\run_demo.ps1" -SkipTests
```

浏览器打开 `http://127.0.0.1:8765`。接入区粘贴准备好的演示事件，正文含虚构手机号 `13912345678`，嵌套元数据含 `demo@example.com` 和虚构 `api_key`。不得使用真实个人数据。

旁白：

> 输入层按记录隔离错误，并对正文和任意深度元数据递归脱敏。疑似提示注入会被标记、降权，并禁止形成长期知识。

### 02:00—02:40 多维偏好

旁白：

> 一个用户可以同时偏好中文、简洁、表格、分步骤、本地处理、先脱敏和高风险确认。每项都有证据 ID、置信度、场景和版本。评分综合质量、来源权威、时效和显式性；失败与取消工具不会成为首选。

操作：滚动展示 `key`、`value`、`confidence`、`version` 和 `evidence_ids`。

### 02:40—03:30 检索与冲突

先查询“报销邮件模板字段”，再打开冲突区。

旁白：

> 检索先限定租户、用户和场景，再用词法索引召回候选；查询向量只计算一次，对候选做语义重排。新旧知识冲突时，新内容先进入待决状态，普通回答看不到它；只有权威和时效足够明确才自动决策，否则等待人工复核。

操作：先展示普通查询不含待决项，再执行 `auto` 决策并刷新。

### 03:30—04:20 安全遗忘

输入“删除报销模板相关记忆”，点击“仅预览影响范围”。

旁白：

> 自然语言删除先生成租户和用户绑定的计划。预览阶段只展示命中词和目标 ID，数据没有变化。确认令牌有效且用户再次确认后，系统才删除正文可见性、倒排索引和向量，并生成不含原始指令和正文的审计回执。

停留 3 秒后点击确认。不要剪掉预览与确认之间的停顿，否则无法证明两阶段机制。

### 04:20—05:05 评测

展示 `artifacts/runtime/latest_evaluation.json` 的 metrics 和一条 details。

旁白：

> 评测不再只奖励命中。多报偏好计入精确率，低相关查询必须返回空答案，授权集合外多删任何目标都计误删。v2 含 120 条合成事件，train、dev、test 各 40 条，覆盖六类场景和跨用户反例。公开 test 是冻结回归分区，不是独立盲测。

### 05:05—05:40 性能

展示 `artifacts/verification/performance_windows_dev.md`，再打开 JSON 的环境字段。

旁白：

> 在 Windows 开发机和 HashEmbedding 下，10,000 条知识的冷查询是 87.620 毫秒，热查询 p99 是 112.732 毫秒，同时报告内存和 SQLite 体积。真实 Kylin SDK 的模型加载和维度可能不同，最终必须在指定系统复测。

### 05:40—06:05 自动化测试

命令：

```powershell
python -m unittest discover -s tests -v
```

旁白：

> 自动化覆盖核心单元、SQLite 迁移、服务集成、HTTP 端到端、性能报告和安全对抗，包括跨租户、提示注入、失败工具、硬删除残留和嵌套凭证。

注意：录制前以最终终端输出复核“65 项”，如有变化需同步更新字幕、手册和 PPT。

### 06:05—06:30 边界与结束

旁白：

> 目前完成的是核心原型与开发机证据。真实 SDK、指定银河麒麟、独立盲测和经同意案例仍需外部闭环。下一阶段完成这四项后，才能宣称赛题指定环境全部达标。谢谢观看。

## 4. 字幕与视觉规范

- 字幕每行不超过 22 个汉字，最多两行；白字配 60% 黑底。
- 关键数字使用同一种强调色，不用红色表示“通过”。
- 所有性能页固定带“Windows / HashEmbedding 开发证据”角标。
- 所有评测页固定带“合成数据；公开 test 非独立盲测”角标。
- 鼠标缓慢移动，重要字段停留 2—3 秒；不要快速滚动。
- 不展示报名表、签名、邮箱、个人桌面、浏览器账户或真实办公文件。

## 5. 失败与备用方案

| 故障 | 现场处理 | 后期处理原则 |
| --- | --- | --- |
| 8765 端口占用 | 改用 `-Port 8766` | 字幕同步改端口 |
| 浏览器打不开 | 直接访问明确 URL，检查 doctor | 不伪造界面结果 |
| SDK 缺失 | 展示 unavailable 报告 | 说明尚未取得，不剪成 ready |
| 测试失败 | 停止录制并修复后全量重跑 | 不只截取通过片段 |
| 终端乱码 | 设置 UTF-8 后重开终端 | 不遮盖关键日志 |
| 性能抖动 | 关闭后台程序并重新完整跑 | 保留新原始 JSON，更新引用 |
| 断网 | 项目应完全离线演示 | 不依赖在线页面 |
