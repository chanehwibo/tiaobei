状态：**已完成初版，待赛事验收**。这是公开合成检索回归，不是独立盲测、真实故障记录、
真实Agent任务成功率或原生SDK成绩。原生SDK仍为**待复测风险项**。

其中6个多文档请求必须找齐两份证据。12个无答案中，6个版本不存在，6个实体/版本存在

填充到1,000/10,000条，0%/75%仅指填充记录中相似干扰比例，固定难例始终存在。

## 代码落实与适用边界

`MemoryStore.search_knowledge`、`MemoryService.search`和HTTP搜索新增可选`required_terms`。
约束是调用方已经明确的实体/版本，逐项要求出现在标题或正文；标签、source_id不能充当证据。
支持拉丁字母全半角与大小写归一，编号/版本按边界匹配，避免短编号吞入长编号。
先通过倒排索引缩小集合，再检查字面证据，最后召回重排和top-k；无授权/匹配候选时不调用编码器。
空约束保留原检索行为，已有全排序参考测试继续检查默认路径。

这是显式检索过滤，不是自动意图抽取、语义蕴含判断或完整事实验证。
实体/版本出现不代表所问关系受到支持，返回片段也不是最终答案。
新增负例专门保留这种情况；不能删除它们后宣称拒答可靠。
使用方不得从正确答案、相关文档ID或隐藏标签生成约束。示例和参数限制见`13_API文档.md`。

## 对照方法

当前同一源码、同一冻结输入，分别关闭和开启约束，使用HashEmbedding256/ngram2、
top_k=3、阈值0.265和`PYTHONHASHSEED=0`，四组规模/干扰配置各三轮，串行运行。
两种模式的返回集合可以改变，因此是输入约束消融，不是等输出加速证明。
第一轮不预热查询；同一进程的时间解析缓存可能已有条目，不称操作系统/模型冷启动。
后两轮复用服务，也不计作新的独立请求。全部失败、异常、首请求、P50/P95/P99和资源记录保留。

计时为`MemoryService.search`完整方法，不含建库、HTTP、Agent推理或SDK初始化。
除全体请求P95外，正例、无答案、作用域分别列P95，避免空集合快返回冲淡正例时延。
相关性、干扰片段、完整证据、拒答、跨域泄漏分别重算；定义沿用第39号文档。

## 当前测量

2026-09-10在Windows开发机上完成8组配置、每组三轮、每轮48个请求。
原始逐请求证据为`artifacts/verification/feedback/followup-20260910/complex_constraints.json`，
包含环境、源码/评测器/数据摘要、资源、全部返回与分层汇总。
24轮仍只有48个不同输入，不能称1,152个独立样本。

### 逐轮服务P95

单位ms；每项依次为第1/2/3轮的48请求P95，不挑最快一轮。

| 记录数 | 相似填充 | 关闭约束 | 开启约束 |
| --- | --- | --- | --- |
| 1,000 | 0% | 8.476 / 9.321 / 7.576 | 1.646 / 1.621 / 1.625 |
| 1,000 | 75% | 8.147 / 8.391 / 8.083 | 2.226 / 2.206 / 2.070 |
| 10,000 | 0% | 39.356 / 40.904 / 39.402 | 12.479 / 11.401 / 11.453 |
| 10,000 | 75% | 41.244 / 39.766 / 42.083 | 16.795 / 16.902 / 16.426 |

1万条/75%首轮全请求P95降低59.3%。因约束改变候选和返回集合，这不是保持输出不变的优化；
只能解释为本组显式输入约束的工作量及质量变化，不能外推原生SDK或任意查询。

### 质量与干扰

下表为1万条/75%首轮；该配置后两轮质量相同。

| 指标 | 关闭约束 | 开启约束 | 分母 |
| --- | --- | --- | --- |
| 正例宏Recall@3 | 91.67% | 95.83% | 24个正例，各题按相关ID计算 |
| 完整证据召回率 | 21/24（87.50%） | 22/24（91.67%） | 24个正例 |
| 无答案正确率 | 2/12（16.67%） | 8/12（66.67%） | 不含作用域负例 |
| 版本不存在正确拒答 | 0/6 | 6/6 | 6个缺版本负例 |
| 关系缺证据正确拒答 | 2/6 | 2/6 | 6个实体/版本存在的负例 |
| 干扰返回占比 | 42/69（60.87%） | 31/59（52.54%） | 正例返回片段，不是请求数 |
| 作用域正确空返回 | 12/12 | 12/12 | 12个作用域负例 |
| 越域泄漏 / 异常 | 0 / 0 | 0 / 0 | 另检查所有请求的每条返回 |

0%相似填充时，关闭约束的正例Recall@3为95.83%；75%时为91.67%。
开启约束在四组配置、全部轮次均为95.83%，无答案正确率均为66.67%。
**召回和时延达到本组研发门槛，拒答仍低于85%；全部复杂质量并未通过。**

开启约束后，6个多文档请求只找齐4个，宏Recall@3为83.33%；
`rollout-q1`和`failover-q1`各缺一份证据。
`rollout-unsupported`、`restore-unsupported`、`export-unsupported`、
`ipc-unsupported`仍返回了不支持所问关系的片段。实体/版本过滤没有解决关系蕴含判断，
保留这些失败，不删题或临时调阈值。返回候选的“误答”不是LLM最终回答错误率。

## 复现

```powershell
$env:PYTHONHASHSEED = '0'
python -X utf8 -S scripts/evaluate_complex_retrieval.py --suite complex_constraints_v1 --constraints compare --sizes 1000,10000 --hard-fractions 0,0.75 --rounds 3 --output artifacts/runtime/constraints-new.json
```

默认退出码检查测量执行和安全；`--require-targets`额外检查召回、无答案和时延门槛。
执行成功不等于质量全部通过。阈值没有根据这48题重新挑选，也不将它们加入原五项分母。
真实案例、第三方隐藏标签和跨设备/原生模型验证仍需独立补充。
