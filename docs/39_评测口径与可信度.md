# 评测口径与性能可信度

状态：**已完成初版，待赛事验收**。本节按反馈中的性能可信度25分组织证据，
不自行推算赛事得分。评测结果只有在数据、源码、模型、环境及计时边界一致时才可比较。

## 证据用途不能混用

| 证据 | 回答的问题 | 不回答的问题 |
| --- | --- | --- |
| 冻结逐请求五项 | 当前实现是否满足公开合成回归的五项门槛及附加安全检查 | 独立盲测、真实用户收益、模型泛化 |
| 复杂干扰回归 | 相似实体、条件、版本、长文及越域干扰下的漏召回、误答和时延 | 不增加原五项分母，不替代未见数据 |
| 独立文件中的开发与追加反例 | 检查实验拒答规则的收益、副作用和失效原因 | 标签仍由开发者可见；独立文件不等于独立盲测 |
| v3及组件消融 | 分区阈值选择、候选路线、缓存、隔离和衰减的局部作用 | 不等同完整论文、真实Agent或原生SDK复现 |
| 原生SDK/正式运行 | 实际模型、系统、资源和端到端任务表现 | 不得由HashEmbedding或单次探针推算 |

## 冻结五项的精确定义

数据：`data/eval/request_regression_v1.json`。
SHA256：`51ce224491a4252b69d282138785b28f4a9b8a64212b512f587dd48bfbcd1a98`。
模型为HashEmbedding256维、ngram=2；top_k=3、统一min_score=0.265。
不同SDK或不同阈值的结果另立配置，不能沿用本冻结门禁。

| 指标 | 分母与公式 | 失败计入规则 | 门槛 |
| --- | --- | --- | --- |
| 偏好准确率 | 68个请求；完整键值集合相同的请求数/68 | 多键、漏键、错值、输入错误都失败；槽位微F1另报 | >=85% |
| 知识召回率 | 60个正例；逐请求`命中相关ID数/标注相关ID数`的宏平均Recall@3 | 标注知识漏入库仍保留该查询并记漏召回；不按所有返回数计算召回 | >=85% |
| 冲突正确率 | 60个独立知识对；检测与新旧记录最终状态都正确的对数/60 | 错检、漏检、错误淘汰、错误自动决策均失败 | >=88% |
| 检索P95 | 80个不同查询：60正例+12无答案+8跨域 | 计时真实服务方法，不删除慢请求；异常使运行失败，不能只报已成功前缀 | <=500ms |
| 敏感识别F1 | 50个请求汇总实体类型与精确原值出现次数；`2TP/(2TP+FP+FN)` | 重复/重叠多检计FP、漏实体计FN；原值泄漏另设零容忍检查 | >=90% |

额外硬门槛：8项长期持久化授权检查全部通过、60条标注知识完整入库、
无答案准确率至少85%（分母仅12）、跨作用域泄漏0/8、脱敏后原值零泄漏。
这些条件与五项数值、分母、数据摘要及配置一起参与退出码，不是可忽略的备注。

80个查询重复三轮仍只有80个不同查询，不能写成240个独立样本。
只有整个运行正常完成且逐条重算与汇总一致，才能认定内部回归通过。

## 复杂干扰集的增补口径

复杂集先冻结数据、相关ID和负例，再作检索实现优化，使用独立文件和摘要。
它是开发者编写且可见标签的公开回归；即使冻结，也不称独立盲测。
语料包括相关知识、同域相似实体与规则、历史/未来版本、待决/隔离记录、
跨租户/用户/场景记录和长文干扰。定向版本/权限记录直接构建受控存储快照，
因此该集检验检索及过滤，不冒充生产接入、冲突检测或授权晋升的额外证据。

逐请求报告以下指标，按场景类别以及语料规模、干扰比例分别汇总：

- 正例宏平均Recall@3及完整证据召回率；多文档问题必须召回全部标注ID才算完整。
- Precision@3使用固定分母3，空位也计入；MRR@3取第一个相关结果的倒数排名。
- nDCG@3使用二值相关性，理想排序按`min(相关文档数,3)`归一化。
- 无答案误答率=`返回非空的无答案请求数/无答案请求数`，不混入权限必空请求。
- 干扰返回率=`正例返回中不相关ID数/正例返回ID总数`，同时报告分子、分母。
- 泄漏按返回记录的租户、用户/共享、场景、状态和有效时间重算；即使相关ID正确也检查额外返回。
- 错误及超时不能因无返回而算正确拒答；单列错误数，质量按失败计，性能有效性为false。

主混合配置沿用0.265，不在新集上逐题改阈值。仅词法/仅向量作为固定配置诊断，
不把它们的分数标度与混合分数视为同一校准器；需要公平最优阈值对比时使用已有v3 dev流程。
新集困难类别低于预期时保留失败ID及完整返回，不通过删除难题、重复易题或改分母修饰结果。

新增`complex_constraints_v1`的48个请求与原120请求分别报告，细节见第41号文档。
每题显式实体/版本约束属于输入，不由标签生成；同一输入分别关闭和开启过滤。
12个无答案中，版本不存在与关系缺证据各6个，必须分开报正确率。
按正例、无答案、作用域单列P95，防止空作用域快返回掩盖正例耗时。
该开关可能改变输出，不套用要求结果完全一致的历史优化比较器，也不宣称通用拒答已解决。

## 实验拒答策略与开发数据

默认`evidence_policy=similarity`保持原相似度路径。可选`content_coverage_v1`只检查
已授权top-k的标题和正文，以预先固定的0.5覆盖规则决定是否整组拒答，不重排、不改分，
不读取相关ID、标签或隐藏记录。默认/实验及显式约束开/关必须分别报告。
比较器核对相同语料、provider、输入与逐请求结果，防止把改分或重排写成单纯拒答收益。

`data/dev/evidence_coverage_v1.json`有20个请求（10正例、10无答案），
追加文件`evidence_coverage_challenge_v1.json`有10个请求（6正例、4无答案），
两者复用同一组10条开发文档。追加反例是在公开复杂对照暴露副作用后补充，
不是预先隐藏的测试。各文件固定字节、来源及分母，不与168个复杂请求合并计分。

初次开发和复杂对照保留为诊断历史；最终同源复杂对照串行三轮，开发各一轮，
所有配置和失败同时披露。三轮不是三倍独立样本，也不从中挑最快轮或只报告高分策略。
词面覆盖不等于关系蕴含：可以误拒有答案的同义问题，也可以放过词汇相近的错误关系。
实验策略不推荐默认启用，具体反例及复测见第44号文档。

## 计时与资源范围

统一使用`perf_counter`，单位毫秒。nearest-rank分位数为排序后第`ceil(p*n)`个观测值，
不使用均值、最大值、插值分位数或“最快一轮”替代P95。

| 测量 | 起止范围 | 另报的成本 |
| --- | --- | --- |
| 冻结五项检索 | 调用`MemoryService.search`之前至返回之后 | 包含服务锁、查询编码、候选、重排和序列化；无预热 |
| 复杂检索各轮 | 相同服务边界，固定查询顺序；首轮无查询预热 | 首次查询单列，后续轮逐轮报告，不池化为独立样本；构建/编码/索引成本另报 |
| HTTP/SQLite混合负载 | 实际HTTP响应、增量写入、持久化重开 | 与进程内检索分表，不从进程内时间推算网络端到端 |
| 原生SDK | 真模型调用与实际服务检索分别测量 | 冷启动、进程/会话初始化、首个检索、稳定服务和异常都记录 |

优化前后必须匹配机器、Python、模型配置、数据摘要、语料内容摘要、规模、干扰比例、
top_k、阈值、查询顺序、重复轮数和评测器摘要；保存两份源码摘要与每次输出。
性能运行串行，记录可用CPU/内存及进程RSS；共享开发机仍有调度噪声，不能称严格实验室隔离。
成对时延只在无错误且质量/隔离不退化时解释为改进；同分也如实报告。

本轮源码核验同时保存原始SHA256和仅CRLF转LF的规范化SHA256：原始报告先绑定
实测Windows快照，再用规范化摘要核对当前检出源码。只容许换行差异，不忽略代码、
参数或标签变化；冻结数据、原始JSON和Office仍按原始字节校验。
当前证据目录为`artifacts/verification/feedback/implementation-20260910/`；
历史配对和`followup-20260910/`中的测量只对应各自历史源码。

## 真实SDK风险和外部验收

## 最小复核清单

1. 核对文件清单、SHA256、源码快照、数据原始字节和模型参数；本轮只做布局预检，不打包。
2. 核对全部请求ID唯一，分母、失败与逐条返回能重算汇总。
3. 分开阅读正例召回、无答案误答、隔离泄漏与各困难类别；不只看平均值。
4. 对比同配置每轮P50/P95/P99、冷首查、构建与内存，不省略最慢轮。
5. 复核原生SDK风险、公开合成范围及外部证据，不把内部数值等同正式认证。
