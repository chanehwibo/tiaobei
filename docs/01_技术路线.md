# 01 技术路线

## 总体路线

采用“规则基线 + 轻量 embedding + 可替换 SDK 适配层 + 量化评测”的路线推进。

仓库已经完成规则 + HashEmbedding 开发基线、SQLite v2、服务/API、浏览器演示、分区合成评测、规模基准和本地交付材料。尚待外部完成的阶段是：接入真实银河麒麟 embedding SDK，在指定系统复测，以及取得独立盲测、授权案例和赛事流程证据。

## 模块拆分

1. 多源数据整合模块：统一接入手动配置、用户行为、会话上下文、工具结果、系统事件和导入文档，做校验、标准化、质量评分、递归脱敏和风险隔离。
2. 偏好记忆模块：按语言、详略、格式、结构、安全和场景工具等维度抽取，支持租户/用户/场景作用域、版本、证据、权威度与时间衰减。
3. 生命周期模块：实现会话短期记忆、重复证据中期聚合、长期晋升/拒绝/过期。
4. 知识模块：沉淀流程、案例、模板与总结，支持类型、有效期、隐私级别、冲突隔离和多种解决策略。
5. 检索模块：词法候选召回、缓存向量重排与权威度融合；通过 `EmbeddingProvider` 隔离 HashEmbedding 和真实 SDK。
6. 遗忘模块：解析自然语言指令，执行作用域绑定的预览、确认、软/硬删除、索引同步与隐私安全审计。
7. 服务与持久化：MemoryService、SQLite v2、本地 HTTP API 和浏览器仪表盘。
8. 评测与交付：多指标评测、性能/兼容性报告、完整验收、隐私扫描和允许列表打包。

## 关键创新点储备

- 多源证据合并：每条记忆保留来源、场景、时间和证据 ID。
- 版本化偏好：同一偏好发生变化时生成新版本，支持回溯。
- 冲突可解释：新知识与旧知识冲突时不直接覆盖，先进入待融合状态，并支持接受新版本、保留旧版本、保留双方、证据合并和人工确认队列等基础解决策略。
- 端侧轻量化：把 embedding、索引和存储都设计成可本地运行。
- 安全记忆：敏感信息在进入记忆前先识别和替换。

## Embedding 适配层

当前原型提供三层能力：

- `EmbeddingProvider`：检索和冲突检测依赖的最小接口，包含 `encode()` 和 `similarity()`。
- `HashEmbedding`：纯标准库离线 fallback，用字符 n-gram hashing 生成轻量向量。
- `CallableEmbeddingProvider`：外部 SDK 适配器，可包装任意 `text -> vector` 的函数。
- `KylinEmbeddingProvider`：面向银河麒麟 embedding SDK 的适配器脚手架，支持直接传入 SDK client 或按模块名动态加载。

待获取银河麒麟 embedding SDK 后，只需把 SDK 的向量生成函数传入 `CallableEmbeddingProvider`，或通过 `KylinEmbeddingProvider` 指定模块名、工厂函数和方法名，即可复用现有 `MemoryStore`、评测和 CLI。

## 当前原型边界

核心运行时是纯 Python 标准库原型，规则和 HashEmbedding 只是离线开发基线，不代表真实银河麒麟 SDK 或开放真实数据性能。仓库中的 120 条分区数据为合成数据，test 标签公开；固定 Windows 性能报告也不能替代指定系统复测。
