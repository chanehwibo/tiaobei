# 测试报告

## 测试目标

验证当前 OS Agent 记忆优化原型是否具备可复现的基础闭环：

1. 多源事件接入、清洗和敏感信息脱敏。
2. 偏好记忆抽取和版本化。
3. 知识记忆抽取、检索和冲突处理。
4. 自然语言遗忘。
5. SQLite 本地持久化。
6. 标注评测指标和逐用例明细输出。

## 测试环境

- 当前执行环境：Windows PowerShell，本地 Python 运行环境。
- 项目路径：`C:\Users\CanhuiBao\Desktop\挑战杯 揭榜挂帅\os-agent-memory-optimizer`
- Python 包依赖：当前原型仅使用标准库。
- 说明：本报告记录的是开发机可复现实验结果，不等同于银河麒麟桌面系统上的最终性能测试结果。

## 数据集

标注评测集：`data/eval/office_memory_eval.json`

当前规模：

- 多源事件：11 条。
- 偏好标注：4 条。
- 知识检索查询：5 条。
- 冲突处理用例：4 条。
- 自然语言遗忘用例：3 条。

覆盖场景：

- 办公报销：流程、模板、失败案例、隐私策略。
- 会议纪要：会议模板、待办责任规则、隐私规则。
- 无关噪声：天气和日历记录。

## 指标定义

- 偏好提取准确率：标注偏好键值中，预测值与期望值一致的比例。
- 知识检索召回率@K：每条查询在 top-K 返回结果中命中期望标题的比例，再对查询取平均。
- 知识检索平均延迟：重复执行检索并统计平均耗时，单位毫秒。
- 冲突处理准确率：冲突识别结果、可选解决策略结果和内容校验均满足标注的比例。
- 遗忘准确率：期望遗忘记忆被遗忘且期望保留记忆未被误删的比例。

## 明细输出

`evaluate` 的完整报告包含 `details`：

- `details.preferences`：偏好标注的期望值、预测值、置信度、版本、场景和证据 ID。
- `details.retrieval`：每条查询的期望标题、返回标题、命中标题、单条召回率。
- `details.conflicts`：每个冲突用例的冲突识别、解决策略、新旧状态和合并内容。
- `details.forget`：每条遗忘指令的关键词、实际遗忘标题、漏删和误删列表。

## 风险和限制

- 当前评测集仍然较小，指标只能证明规则基线和评测链路有效。
- 检索延迟来自本地小样本 HashEmbedding，不代表大规模知识库或真实 SDK 性能。
- 银河麒麟 embedding SDK 尚未在本机接入，当前仅完成适配器脚手架。
- 偏好抽取仍以规则为主，对复杂表达和长期偏好漂移的鲁棒性不足。

## 后续测试计划

1. 扩展评测集到至少 100 条多源事件，加入更多跨场景和失败样例。
2. 在银河麒麟桌面系统上复测检索延迟、SQLite 读写和 SDK embedding 调用。
3. 增加误删率、冲突人工确认耗时、偏好版本稳定性等细分指标。
4. 增加批量评测脚本，输出可归档的 JSON 和 Markdown 报告。
