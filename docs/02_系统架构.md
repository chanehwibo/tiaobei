# 02 系统架构

## 数据流

```text
多源输入
  -> 校验 / 去重 / 时间归一 / 递归脱敏 / 风险检测
  -> 带 tenant / user / session 的 DataRecord
  -> 短期 / 中期 / 长期生命周期
  -> 偏好抽取 / 知识抽取
  -> MemoryStore + 缓存向量索引
  -> 作用域检索 / 冲突隔离 / 两阶段遗忘
  -> MemoryService / HTTP API / 评测
  -> SQLite v2 本地持久化与审计
```

## 记忆类型

### 偏好记忆

字段包括租户、用户、偏好键、偏好值、置信度、版本、场景、证据 ID、来源权威度、有效时间、更新时间和状态。

典型偏好：

- `output.language` / `output.verbosity` / `output.format` / `output.structure`
- `security.processing` / `security.redaction` / `security.confirmation`
- `preferred_tool:<scene>`: 某场景下优先使用的工具

### 知识记忆

字段包括租户、用户、标题、正文、标签、来源 ID、类型、场景、权威度、隐私级别、有效期、生命周期、版本、缓存向量、状态和冲突对象。普通检索只返回当前作用域内的 `active` 记忆。

典型知识：

- 工作流程：报销流程、审批流程、文档处理流程。
- 历史案例：失败原因、解决方案、复盘结论。
- 可复用模板：邮件模板、报告模板、表格模板。

### 知识冲突处理

当前冲突处理分两步：

1. 入库时通过标题相似度、共享标签和矛盾词对识别冲突，新知识先标记为 `conflict_pending`。
2. 通过 `resolve_knowledge_conflict()` 执行基础解决策略：

- `accept_incoming`：接受新知识，并将冲突旧知识软删除。
- `keep_existing`：保留旧知识，将新知识软删除。
- `keep_both`：保留双方，清除待处理冲突状态。
- `merge` / `evidence_merge`：根据来源权威度、有效时间和版本选出有效主张，只合并标签与证据 ID，不把互相矛盾的正文拼接成一条知识。
- `auto` / `authority_recency`：优先比较来源权威度，再比较有效时间；证据不足时保留为待人工确认。
- `manual_review` / `manual_queue`：保留待处理状态，交由后续人工确认队列处理。

## 与短期、中期记忆的交互

短期记忆负责当前会话上下文，例如用户刚上传的文件、当前任务步骤、临时工具结果。中期记忆负责一段时间内的项目状态、近期偏好和半稳定知识。长期偏好/知识记忆只接收经过质量校验和价值判断的信息。

建议流转规则：

1. 短期记忆产生事件和工具结果。
2. 中期记忆聚合一段时间内的重复行为和上下文。
3. 本项目模块对中期聚合结果和高质量短期事件做抽取。
4. 高质量、重复或高权威证据才进入长期偏好记忆或知识记忆；可疑内容被拒绝或隔离。
5. Agent 执行任务前，从长期记忆检索相关偏好和知识，注入当前上下文。

## 本地持久化

当前原型新增 `SQLiteMemoryPersistence`，用于把内存中的偏好记忆、偏好版本历史和知识记忆保存到本地 SQLite 文件。

设计原则：

- 不改变 `MemoryStore` 的核心读写接口。
- 使用 JSON 字段保存列表型结构，例如场景、证据 ID、标签和冲突对象。
- 软删除保留可审计状态，硬删除移除正文、记录和向量；两者都同步索引。
- 保持纯标准库实现，方便在银河麒麟桌面环境离线运行。

运行命令：

```powershell
$env:PYTHONPATH="$PWD\src"
python -m os_agent_memory.cli build-store --input ".\data\samples\events.jsonl" --output ".\artifacts\runtime\memory.sqlite"
```
